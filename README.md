# Office Inventory API

FastAPI + SQLAlchemy service for tracking office equipment and supplies.

## Setup

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/alembic upgrade head        # create/update the schema
.venv/bin/fastapi dev app/main.py     # http://127.0.0.1:8000/docs
```

Database defaults to SQLite (`./inventory.db`). Override with `DATABASE_URL`, e.g. `postgresql+psycopg://user:pass@localhost:5432/inventory`.

Use Postgres anywhere more than one request can write at once. Stock and assignment changes take a row lock on the item (`SELECT ... FOR UPDATE`) so concurrent requests can't over-assign; SQLite ignores row locks.

### Docker

Runs Postgres, the [Laravel users API](../office-users-api) and this API together. Needs `office-users-api` checked out next to this repo.

```bash
echo "USERS_APP_KEY=base64:$(openssl rand -base64 32)" > .env   # once
docker compose up -d --build --wait
```

| Service | URL |
|---|---|
| Inventory API | http://localhost:8001/docs |
| Users API | http://localhost:8000 |
| Postgres | `localhost:5432`, user/password `postgres` (databases `inventory`, `users`) |

On first start `users-init` seeds the demo accounts (`admin@example.com` / `staff@example.com`, password `password`) and writes the inventory API's service token to a shared volume; later starts reuse both. Both APIs run migrations on startup (`RUN_MIGRATIONS=0` disables that). Get a token to try things:

```bash
curl -s -XPOST localhost:8000/api/login -H 'Accept: application/json' -d email=admin@example.com -d password=password
```

`docker compose down -v` wipes the databases and the token.

### Migrations

Schema is managed by Alembic (`migrations/`); the app does not create tables on startup.

```bash
.venv/bin/alembic revision --autogenerate -m "describe change"   # after editing app/models.py
.venv/bin/alembic upgrade head
```

Review autogenerated files before committing. `tests/test_migrations.py` fails if models drift from migrations.

**Existing database from before Alembic** (tables created by the old startup `create_all`): mark it as the initial schema, then upgrade:

```bash
.venv/bin/alembic stamp 0001
.venv/bin/alembic upgrade head
```

Assignments created before `0002` get `user_id = 0` (unknown user). Rows from before `0003` have no audit actors (`assigned_by_user_id` etc. are null) and no stock movement history.

### Users (Laravel)

Users live in a separate Laravel API. Configure via env (see `.env.example`):

| Variable | Purpose |
|---|---|
| `USERS_API_URL` | Laravel base URL, e.g. `https://hr.example.com` |
| `USERS_API_TOKEN` | Sanctum token, sent as `Authorization: Bearer ...` |
| `USERS_API_TOKEN_FILE` | Alternative to `USERS_API_TOKEN`: path to a file holding the token (takes precedence) |
| `USERS_API_TIMEOUT` | Seconds, default `5` |

Expected Laravel endpoints (standard API Resource shape):

- `GET /api/users?page=N` returns `{"data": [{"id", "name", "email"}, ...]}`
- `GET /api/users/{id}` returns `{"data": {"id", "name", "email"}}`, or 404

Creating an assignment looks up the user and snapshots name/email onto the record, so history and `/users/{id}/assignments` keep working if Laravel is down or the user changes. Unknown user returns 422; Laravel unreachable or unconfigured returns 503.

### Authentication

Every endpoint except `/health` requires `Authorization: Bearer <token>`, where the token is the caller's own Laravel Sanctum token. It is resolved by calling Laravel's `GET /api/user` with that token (the default `auth:sanctum` route), so that response must include the user's `id`, `name`, and the admin field below.

| Variable | Default | Purpose |
|---|---|---|
| `AUTH_ADMIN_FIELD` | `role` | Field on the `/api/user` payload that marks admins |
| `AUTH_ADMIN_VALUES` | `admin` | Comma-separated values that count as admin |
| `AUTH_CACHE_TTL` | `60` | Seconds to cache a successful token lookup (`0` disables) |

The admin field may be a string (`"role": "admin"`), a boolean (`AUTH_ADMIN_FIELD=is_admin`), a list (`"roles": ["admin"]`), or Spatie-style role objects (`"roles": [{"name": "admin"}]`).

Responses: no/invalid token returns 401; non-admin on an admin route returns 403; Laravel unreachable on an uncached token returns 503. A revoked token keeps working until its cache entry expires (up to `AUTH_CACHE_TTL` seconds). The cache is per process.

## Resources

Access: **any** = any authenticated user, **admin** = admin only.

| Endpoint | Access | Purpose |
|---|---|---|
| `GET /categories`, `GET /locations`, `GET /items[...]` | any | Read catalog, including `/items/summary` |
| `POST`/`PATCH`/`DELETE` on `/categories`, `/locations`, `/items` | admin | CRUD for categories, locations (rooms / floors / buildings), items |
| `GET /items` filters | | `q`, `category_id`, `location_id`, `status`, `low_stock`, `skip`, `limit` |
| `POST /items/{id}/adjust` | admin | Add/remove stock (`{"delta": -2, "reason": "broken"}`) |
| `GET /items/{id}/movements` | admin | Quantity history: `initial`, `adjust` (with reason), `edit` (PATCH), each with acting `user_id` |
| `/assignments` | admin | Check items out to users (`{"item_id": 1, "user_id": 12}`); filters `item_id`, `user_id`, `assignee`, `active` |
| `POST /assignments/{id}/return` | admin | Check an item back in |
| `GET /users`, `GET /users/{id}` | admin | Proxied from Laravel |
| `GET /users/{id}/assignments` | admin | Items a user holds (local data); filter `active` |
| `GET /me` | any | The caller, with `is_admin` |
| `GET /me/assignments` | any | Items the caller holds; filter `active` |

Rules: an item can't be assigned beyond its available quantity or while `in_repair`/`retired`; its quantity can't drop below what's assigned; items with open assignments can't be deleted. Low stock = available ≤ `reorder_level`.

Audit: every quantity change writes a stock movement; assignments record `assigned_by_user_id` and `returned_by_user_id` (Laravel user IDs of the acting admin).

## Tests

```bash
.venv/bin/pytest
```

Lint and format (also run in CI):

```bash
.venv/bin/ruff check . && .venv/bin/ruff format --check .
```

Runs on in-memory SQLite by default. To also run the Postgres-only concurrency test, point it at an empty scratch database (it is wiped by each test):

```bash
TEST_DATABASE_URL=postgresql+psycopg://postgres@localhost:5432/inventory_test .venv/bin/pytest
```
